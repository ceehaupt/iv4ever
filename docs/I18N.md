# Übersetzung (i18n) – Bestandsaufnahme und Optionen

Stand 27.11.2026. Noch keine Entscheidung – Vorschlag unten.

## Wo stehen Texte?

Zählung deutscher Zeichenketten im Code (grobe Heuristik, eher zu niedrig):

| Bereich | Texte | Art |
|---|---|---|
| `index.html`, `editor.html` | ~35 Stellen | Menüs, Dialoge, Knöpfe |
| `src/ui/` (13 Dateien) | ~110 | Panels, Tooltips, Handbuch-Rahmen, Tutorial |
| `src/main.ts`, `render/`, `editor/`, `net/`, `worker/` | ~75 | Meldungen, Lobby, Editor |
| `src/sim/` (Logik) | ~130 | **Ereignismeldungen (`events.push`) und Fehlermeldungen (`CommandError`)** mit eingesetzten Namen/Zahlen |
| `src/sim/rules/` (Daten) | ~100 + alle Namen | Einheiten, Gebäude, Technologien, Leitbilder, Beschreibungen – jeweils mit stabilem `key` |
| `server/relay.mjs` | 4 | Fehlermeldungen an Clients |
| Erzeugt | – | `docs/REGELN-DATEN.md`, Handbuch-Tabellen (`catalog.ts`) |

Besonderheit: Die **Simulation erzeugt fertigen deutschen Text** (z. B. `` `${p.name} wurde vernichtet` ``). Im Online-Spiel
rechnen alle Clients dieselbe Simulation – Texte dürfen also nicht von der Sprache des Clients abhängen, solange sie in
der Simulation entstehen.

## Optionen

**A – Schlüssel + Parameter, eigenes Mini-Modul (empfohlen)**
`t('event.destroyed', { name })`, Sprachdateien `src/i18n/de.ts`, `en.ts` (typgeprüft: fehlende Schlüssel = Compilerfehler).
Die Simulation liefert statt Text `{ key, params }`; erst die UI übersetzt.
+ keine Abhängigkeit, typsicher, Simulation bleibt sprachneutral (Lockstep-sicher), Regeldaten nutzen die vorhandenen `key`s
− größter Umbau (~220 Meldungsstellen in der Simulation), `TurnEvent`/`CommandError` ändern sich

**B – Deutscher Text als Schlüssel (gettext-Stil)**
`t('Stadt gründen')`, Übersetzungstabelle de → en.
+ wenig Umbau in der UI, Quelltext bleibt lesbar
− Meldungen mit eingesetzten Werten aus der Simulation lassen sich nur über Muster übersetzen (fehleranfällig);
  jede Textänderung bricht die Übersetzung stillschweigend

**C – Bibliothek (z. B. i18next)**
Wie A, aber mit fertigen Plural-/Formatregeln.
+ ausgereift, Plural/Interpolation geschenkt
− Abhängigkeit und Bundle-Größe für etwas, das A mit ~50 Zeilen abdeckt

## Vorschlag zur Umsetzung (bei A)

1. `src/i18n/` mit `t()`, `de.ts` als Quelle, Sprachwahl in ⚙ (localStorage, Standard: Browsersprache, sonst Deutsch).
2. `index.html`/`editor.html`: `data-i18n="…"`-Attribute, beim Start ersetzen.
3. UI-Dateien umstellen.
4. Regeldaten: Namen/Beschreibungen über `key` nachschlagen (`unit.settler.name`), `catalog.ts` sprachabhängig.
5. Simulation: `TurnEvent.text` → `{ key, params }`, `CommandError` mit Schlüssel; Übersetzung im Hauptthread.
6. Test: alle Sprachdateien haben dieselben Schlüssel; `de` deckt jeden verwendeten Schlüssel ab.
